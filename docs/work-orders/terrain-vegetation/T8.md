Freeze: species

T8 adds tree forms that say something the three LOLIPOP species cannot (plan section 6, user decision question 6):
- a **willow or alder** form that marks calm water from a distance;
- a pale-trunked **birch or aspen** form for wet and disturbed ground;
- a **broad solitary crown** for open woodland.

More fir variants are a possible fourth item. Only CC0 or CC-BY assets are allowed. Every new tree uses the existing four-LOD import path, with crossed cards as LOD3, so the shared far impostor takes it unchanged. New variants are appended after every existing index. Earlier generations never see them.

"Further assets" means whatever the user asks for at G3. Each such asset follows the pattern of T8-4 (import) and T8-7 (placement), with its own selection row in T8-1.

## Phase facts

Verified on branch `gpu-offload`, 2026-11-10, against the code as it was before T6. **T6 changes the catalog, the placement and the shader.** Each WO therefore re-reads the post-T6 code. Facts T6 is expected to change are marked "(T6 changes)".

**Catalog and import (C#)**

- F1. `scripts/Vegetation/ImportedTreeCatalog.cs`:
  - `enum TreeSpecies { Maple, Fir, Pine }` (line 8).
  - `CatalogVersion = 1` (line 43) and `VariantCount = 30` (line 44) (T6 changes: appended snag, log and stump variants).
  - Species order `Maple, Fir, Pine` (line 46).
  - Sources are loaded from `res://resources/trees/lolipop/{species}/scene.gltf` (line 81), with hard-coded per-species counts 12/3/15 (line 94).
  - Trunk-size heuristics are per species (lines 116-117).
- F2. Same file, LOD and material conventions:
  - LOD anchors are nodes named `<Name>_LOD0` to `_LOD3`. Names containing `_Mat_0` are ignored, and a `_Billboard` suffix is stripped (`TryParseLodAnchor`, lines 128-140).
  - The production material is `res://materials/imported_tree.gdshader` (`CreateProductionMaterial`, line 217).
    - Mode 2 (billboard) is chosen when the source material's `ResourceName` contains "Billboard" (line 235).
    - Mode 1 (alpha cutout) is chosen for any non-opaque source material (line 234).
    - Maple bark reads metallic-roughness from UV2 (line 242).
- F3. The species counts and heuristics are duplicated elsewhere:
  - `ImportedTreeCatalog.Startup.cs:69, 87-88`;
  - species-by-index mapping in `PreparedImportedTreeCatalogValidation.cs:29` and `ImportedTreeCatalogRegressionSmoke.cs:19` (index < 12 maple, < 15 fir, else pine) (T6 changes).
- F4. Placement in `scripts/Voxel/LOD/RingBiomeDecorationLayer.TreeStreaming.cs`:
  - species then variant are selected at lines 1163-1164;
  - `SelectForestSpecies` uses `MapleWeight` and `FirWeight`, with pine as the remainder (lines 1279-1284);
  - `SelectForestVariant` uses fixed index ranges (lines 1286-1291);
  - the disk-cache reader rejects variants outside those ranges (lines 1324-1333), with `VegetationDiskCacheVersion = 4` (line 59);
  - the tile hash mixes `CatalogVersion` and `VariantCount` (lines 1512-1515).
  - `ForestRegionSample` carries `MapleWeight`, `FirWeight` and `PineWeight` (`scripts/Vegetation/ForestRegionSampler.cs:20-27`).
  - (T6 changes all of these: communities, stand age, habitat species, size classes.)
- F5. Far impostor in `scripts/Vegetation/ImportedTreeImpostorCatalog.cs`:
  - Every variant's LOD3 must be **one surface** (lines 53-56).
  - All LOD3 meshes are expanded into one shared mesh whose width is the **maximum** expanded vertex count over all variants (lines 47-63). That is 108 today (maple, 36 triangles; T0 8.4).
  - Each variant gets one layer in three `Texture2DArray`s at `TextureLayerSize = 256` (line 11).
  - A new LOD3 with more than 108 expanded vertices would widen the shared mesh and the data textures for every earlier variant.
- F6. Pack facts from T0 8.4:
  - LOD0-LOD2 have exactly two surfaces, bark then foliage. LOD3 has 64 triangles or fewer (maple 36, fir 20, pine 16).
  - Pine LOD3 lacks metallic and roughness maps, and the packer substitutes a constant fallback (`PackMetallicRoughness`).
  - The visible LOD0 to LOD2 switch is set by the quality preset (Medium 20-30 m, High 25-40 m).

**Prepared catalog pipeline**

- F7. `tools/prepare_tree_assets.ps1` and `tools/prepared_tree_assets_common.ps1`:
  - The pipeline imports, bakes into a staging folder, validates with `tools/check_prepared_tree_assets.ps1`, then promotes `resources/trees/prepared/lolipop_catalog.res` and its `.manifest.json`.
  - The input list is hard-coded to `resources/trees/lolipop/{fir,maple,pine}` (`prepared_tree_assets_common.ps1:6-15`).
  - The manifest records `catalog_version`, `source_fingerprint`, `implementation_identity` and per-input SHA-256 values.
  - The import step greps stderr for `lolipop/(fir|maple|pine)/scene.gltf` import errors (`prepare_tree_assets.ps1:38`).
- F8. Fingerprint: `tools/WorldGenerationFingerprint.cs:169-184` hashes every catalog variant plus `variant_count` and `CatalogVersion` into the generation 1 row (T6 decides how appended variants keep earlier rows stable).
- F9. Textures: LOLIPOP textures import as VRAM-compressed with mipmaps (`compress/mode=2`, `mipmaps/generate=true`, for example the maple billboard `.png.import` lines 19 and 27). Source sizes (T0 8.4):
  - maple bark and leaf clusters 2048, billboards 1024;
  - pine bark 1024 x 2048, needles 2048;
  - fir bark 2048 x 4096, boughs 4096.

**Licences and attribution**
